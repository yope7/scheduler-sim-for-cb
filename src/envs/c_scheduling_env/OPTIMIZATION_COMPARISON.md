# 最適化前後の比較

## 最適化のポイント

### 1. データ構造の最適化
**最適化前:**
- 構造化配列からndarrayへの変換が毎回発生
- `np.ascontiguousarray()`が頻繁に呼ばれる
- メモリコピーが発生

**最適化後:**
- ウィンドウの状態をC連続配列として直接保持
- データ変換が不要
- メモリコピーを削減

### 2. キャッシュ管理の最適化
**最適化前:**
- 毎回`WindowCache`を構築
- データ変換が発生

**最適化後:**
- C連続配列を直接使用してキャッシュを構築
- データ変換が不要

### 3. メモリ管理の最適化
**最適化前:**
- PythonとCの間でデータがコピーされる
- 構造化配列と通常の配列の変換が発生

**最適化後:**
- C連続配列を直接保持
- メモリコピーを最小限に抑える

## 期待される効果

1. **データ変換の削減**: `np.ascontiguousarray()`の呼び出しを削減
2. **メモリコピーの削減**: データ変換時のメモリコピーを削減
3. **キャッシュ構築の高速化**: C連続配列を直接使用してキャッシュを構築
4. **全体的なパフォーマンス向上**: 上記の最適化により、全体的なパフォーマンスが向上

## 測定方法

以下のコマンドで最適化前後のパフォーマンスを比較できます：

```bash
# 最適化前（C実装版）
python test_large_scale_timing_c.py --nb_jobs 1000 --profile --profile_output before.prof

# 最適化後（最適化版）
python test_large_scale_timing_optimized.py --nb_jobs 1000 --profile --profile_output after.prof
```

## 注意事項

- 最適化版は既存の`SchedulingEnv`と互換性を保ちます
- 構造化配列との同期が必要な場合は、`_sync_from_c_arrays()`と`_sync_to_c_arrays()`を使用します
- パフォーマンス測定時は、同じジョブセットを使用して比較してください
