# PCN の週次運用実験: 定義と段階計画（2026-08-30 v2・critic審査反映済み）

目的: 「運用者が毎週 PF から1点を選び、その指令で1週間スケジュールし、その週のジョブで学習を続け、PF を更新して次週に渡す」という運用が成立するかを検証する実験の、設計と定義。

結論を先に: **実験は4段に分け、第0段は学習なしで1日でできる**。第1段も新規学習は実質1本(M_A)＋適応1本で、腕の1つ(週予算スクラッチ)は既存の fast100 がそのまま流用できる。

**本実験の結論の言明範囲(事前登録)**: 12月の隣接4週(ジョブ数 43,700〜64,322、ρ 0.52〜0.68、±30%級のドリフト)に限る。年間の週次ジョブ数は 556〜89,554 と2桁変動しており、激しいドリフトへの一般化は本設計では原理的にできない(第0段0aで位置づけだけ示す)。

---

## 0. 前提: 7月の週次実験と今回の違い

7月の S1/S2/S4 系列は「前週の窓(256〜4096ジョブ)で学習 → 凍結した重みで未知週へ窓ごとに指令を出し直しながら適用」だった。総括は「全構成が未知週カバー率80%基準を落とした。生き残った説明は窓→週スケール転移の壁」。

今回は当時の壁の**一因が除去されている**(消えた、とまでは言わない):

| | 7月 S系列 | 今回 |
|---|---|---|
| 学習単位 | 窓(≤4096)→週へ転移 | 週まるごと1エピソード(5〜6.4万ジョブ)を直接学習(4.3h/100iter@50k) |
| 容量 | cap22700 (weekA ρ=1.10 / weekB ρ=1.43 過負荷) | cap48000 (weekA ρ=0.52 / weekB ρ=0.68 正容量) |
| コード | label_G バグ・REF_PF 混入あり | 08-06/07 修正済み |
| 学習の継続 | なし(毎週スクラッチ) | 本実験の主題 |

**残っている壁(自覚した上で進む)**: wait 軸の条件付けは現行最良モデルでも点滅する(v10 は iter60 のみ点灯)。運用者の選択は実質**コスト1次元のダイヤル**に縮退している。これは実験を無効にしない(達成前線は256指令掃引で得る)が、成果の言い方を制約する。

## 1. 運用プロトコルの定義

### 1.1 役者と時計

- **運用者**: 週に1回、PF から1点選ぶ人。
- **スケジューラ**: 選ばれた指令で greedy 実行する PCN(決定論)。
- **学習器**: 週が閉じた後にその週のトレースで学習する。
- 時計は1つ: **週 = 1エピソード**。窓・指令リセットは使わない。

### 1.2 週 t のループ（既定形）

```
入力: モデル M_t (週 t-1 までのデータで作られた)、前週トレース T_{t-1}
1. 提示   PF_t = M_t を T_{t-1} 上で指令掃引した予測前線
          (=「先週と同じ負荷なら、この取引ができます」という約束)
2. 選択   運用者が1点 π_t を選ぶ
3. 適用   週 t のジョブ列に π_t の指令で greedy 実行(指令は毎手 dr -= reward で自動追跡)
4. 記録   達成 (c_t, w_t)。約束とのずれ = 本実験の主要な従属変数
5. 学習   週 t が閉じたら T_t を教材に、M_t から warm start で継続学習 → M_{t+1}
          (時間予算 = 一晩 8h。注: この予算では毎週スクラッチ(100 iter ≈ 4.3-7h)も可能であり、
           warm 継続はスクラッチに勝って初めて正当化される)
6. 次週へ
```

### 1.3 定義上の決定事項

**D1. 提示 PF は「前週トレース上の予測」と定義する。** 約束と実現のずれがドリフトの定義そのもの。測り方は lockstep 一様指令掃引(256指令 ≈ 9-12分/週)。

**D2. 運用者の座標系は無次元。測定座標も固定する(後から選ばない)。**
- 週 w のコスト座標: X_w = 達成コスト ÷ C_cloud(w)(その週の全ジョブをクラウドに出した費用。ジョブ列から確定計算できる)
- 待ち座標: Y_w = 平均待ち秒(生値)
- 帯: X の5帯 [0,10)/[10,25)/[25,50)/[50,75)/[75,100]%(記述用)
- 等コスト待ち比: X をそろえ、比較対象の階段包絡に対する比。補間は X 軸上の右連続階段(達成点の非支配包絡)。**帯に点が無い場合は「点なし」を明示報告し勝敗に数えない**
- 較正定数(frac→実値)は毎週、前週実績から更新する(S4 carry 暴走の一因=学習時凍結較正の58%ずれ)

**D3. 予算の繰越(carry)は封印。fixed のみ。** S4 でワインドアップ暴走済み(ρ=-0.40、誤差64%)。

**D4. 学習は「週末バッチ再演」。週の途中では学習しない。** 週トレースをシミュレーション上で再演し、通常のオンライン学習(指令多様な rollout)を回す。

**D5. ワークロード外生性を仮定する。** ジョブ到着はスケジューリングに依存しないとする。この仮定の下では**運用者がどの点を選んでも学習データは変わらない**ため、第0〜2段に選点の機構は不要で、全指令の掃引が「あらゆる選択」を一度に評価したことになる。選点が意味を持つのは第3段(占有の引き継ぎ)だけ。

**D6. 週境界の持ち越し規定(既定案)。**

| 対象 | 既定 | 理由 |
|---|---|---|
| モデル重み | 持ち越す(warm) | `DISTRIBUTED_PCN_INIT_CHECKPOINT_PHASE3` 実装済み。**ただし §2 G6 の注意(Phase3直前ロード・strict=False)を守ること** |
| replay/アーカイブ | 捨てる | 間引きが週を区別しない。旧週データの占拠事故が実証済み(08-05) |
| frozen PF | 捨てる | best-ever 無期限保持は追従の錨に反転する |
| 指令正規化 scale | 自動(新プロセス再開の初回 learn で新週レンジへ直代入) | `PCN_ADAPTIVE_RETURN_NORMALIZATION` 既定ON。週境界は「新プロセス再開」で切る |
| 運用者向け較正 | 前週実績で毎週更新 | D2 |
| 資源の占有状態 | 第0〜2段: 各週独立(空スタート) / 第3段: 連続 | 週頭の混雑引き継ぎ(Wall A)は第3段で扱う |

**D7. モデルの checkpoint 選定規則(解析自由度の封印)**: 常に**最終 iter(=100)を使う**。根拠: 外部一様格子での5 checkpoint 選抜(08-30)で iter100 が単調に最良(正規化HV 0.8524→0.9276)。「iter80 ピーク」は内生計器のアーティファクトだった。

**D8. 週境界をまたぐジョブの扱い(帰属と物理を分ける)。**
- 帰属: ジョブは**到着時刻**で週に属する。実行が翌週に食い込んでも、コストと待ちは到着週に全額計上
  (約束=「この週に到着するジョブへの意思決定の総量」。二重計上なし)。エピソードは7日で打ち切らず、
  全ジョブを置き切るまで走る(makespan>7日は仕様)。
- 物理: はみ出した実行は翌週の資源を食う。実測(08-30、待ち0仮定の下限): weekA はまたぐ383件(0.6%)が
  週の仕事量の20.6%を運び、はみ出しは翌週容量の6.9%相当、最悪は境界から8.9日先。weekB は 13.5% / 4.2% / 3.9日。
  - 第0〜2段: 各週空スタートで**意図的に無視**(約束も実現も同じ規約=内部整合、全腕同じ扱い=公平)。
  - 第3段: eval_weekly_rolling の規約(占有は連続、境界で切替は指令だけ)を窓=1週で使い、連鎖を1本の
    連続ストリームとして流す。学習側に残る空スタート不整合=Wall A は、必要になったら
    スナップショット・リスタート(設計済み・未実装)を入れる。
- 注意: yml の exclude_largest_outlier は最大1本(weekA は pt≈10日)を除去するが、8.9日級のはみ出しは残る。

### 1.4 危ないと分かっている断層（設計に織り込むもの）

1. **指令正規化の2相挙動**: scale はモデル buffer 焼き込みだが、学習ループが毎 iter replay p99.5 で上書き(EMA 0.05、新プロセス再開なら初回直代入)。⇒ **適応腕は再較正を「無料で」受け取る = 学習効果と交絡する。腕1.5(§3)で分離する。**
2. **転移の非対称性**: 縮小方向(大→小)だけ崩れる(07-16)。weekA(64,322)→weekB/C(≈50,000)は縮小方向。**第1段の M_A は weekA_full で学習し、この危険方向を統制条件下で通す。**
3. **horizon の焼き付き**: scaling_factor[2]=1/n_jobs が構築時固定。隣接週の N 差は3%程度なので主要因子とせず、記録のみ(感度掃引は後回し)。
4. **実行可能集合の分断**: 巨大ジョブがつくる実現不能帯は週ごとに動く(weekA 最大ジョブ 6.6e7 は weekB 最大 3.3e7 の2倍)。約束ずれの一部は問題の性質。§3.2 の分解手順で区別する。
5. **評価の鉄則**: フラグ一致(起動拒否ガードあり)・CG_MAX(Fourier エイリアス)・jobs_set クラス変数の罠(同一プロセスで2週の env を作らない)・workload 一致。

## 3. 段階実験

### 3.0 データ使用のガント

```
              12/01     12/08     12/15     12/22     12/29
               week0     weekA     weekB     weekC
               43,700件  64,322件  50,279件  48,777件
               (第3段)   ρ=0.52    ρ=0.68    (G2で切出)
第0段 M_B      ·         推論      学習+自己  推論      ← 主役は weekC(順向き)。weekA は逆向き+拡大方向の参考
第1段(全腕を weekC で評価する)
  M_A 学習     ·         学習      ·         ·
  腕0 pd較正   ·         ·         較正      推論      ← 無学習の運用可能ベースライン
  腕1 凍結     ·         (M_A)     ·         推論      ← 2週前のモデルのまま
  腕1.5 再較正 ·         (M_A)     scaleのみ  推論      ← 重み凍結+正規化だけ更新(交絡の分離)
  腕2 適応     ·         (M_A)     適応      推論      ← +weekB推論はin-sample上限(診断用)
  腕3 週スクラッチ ·     ·         学習(=fast100) 推論   ← 一晩予算の対抗馬。学習済み
第3段 連鎖     学習      適応      適応      ·
      推論     ·         推論      推論      推論      ← 常に「学習データの1週先」で評価
```

**設計の核**: 腕0〜3 は全て「情報の締切 = weekB 終了時点」で揃い(腕1のみ意図的に weekA 締切)、
評価は全腕 weekC = 一様に前向き・未知週。比較の意味が揃う:
- 腕2 vs 腕1 = 適応の利得(1週ぶん新しいデータの価値)
- 腕2 vs 腕1.5 = **重みの学習の利得(再較正効果を除いた正味)**
- 腕2 vs 腕3 = warm start の利得(同じ weekB 教材、初期重みだけ違う)
- 各腕 vs 腕0 = PCN を運用する価値そのもの(同じ1週遅れハンデの pd に勝てるか)

### 3.1 第0段: 凍結モデルのドリフト測定(学習なし・1日)

fast100(=M_B, weekB学習, iter100)を使う。

- **0a. 事前分析**(G5): week0/A/B/C の統計 + 年間52週の中での位置づけ。
- **0b. 基準ずれ**: M_B を weekB で自己再現掃引(評価フラグ完全一致の測定は 08-30 の ckpt_select で実施済み: `uniform_pf_it100.npz`)。約束ずれのベース(モデル固有分)。
- **0c. 順方向ドリフト(主役)**: M_B を weekC で掃引。運用の向き・規模差3%。**ドリフト検出の事前登録: weekC でのずれ中央値が 0b の2倍を超えた帯を「ドリフト帯」と呼ぶ。**
- **0d. 逆方向+拡大(参考)**: M_B を weekA_full で掃引(時間と逆向き・拡大方向)。0c との対比で方向の非対称性の初観測。
- **0e. 参照線**: weekC(と weekA)の family_sweep + p掃引(G7 実測を兼ねる)。
- **0f. 腕0 の予行**: weekB で較正した pd の選点を weekC に適用し、M_B→weekC と等コスト待ち比で比較。**第0段だけで「凍結 PCN vs 同ハンデ pd」の初回戦が出る。**

### 3.2 ずれの分解手順(G8)

約束ずれ = ①ベース分(0b: 同じ週での自己再現ずれ) + ②実現不能分 + ③ドリフト起因のモデル分。
②の近似: 週の巨大ジョブ上位 k 本(k≈18、head18 全列挙の手法を上位k抽出に転用)の組合せ列挙で実現可能コスト帯の包絡を作り、family_sweep 到達点で下から支持する。約束点が包絡外なら「物理的不能」に分類し、モデルの罪から除く。

### 3.3 第1段: 適応の6腕対照(新規学習は M_A 1本+適応1本・2〜3日)

- **M_A**: weekA_full(64,322, cap48000)で fast100 レシピ 100 iter(≈5-7h、一晩)。
- **腕0 pd較正**: weekB の掃引で選んだ p を weekC に適用(無学習)。
- **腕1 凍結**: M_A → weekC。
- **腕1.5 再較正**: M_A の重み凍結、指令正規化 scale だけ weekB レンジに設定 → weekC。(運用で使う形は「前週レンジで較正」だが、腕2 が受け取る再較正と条件を揃えるため weekB レンジとする。)
- **腕2 適応**: M_A から warm start、weekB(head50000, fast100 と同一 config)を教材に継続学習。**K は固定しない**: 5-10 iter ごとに checkpoint を保存し lockstep で軌跡評価する(warm 継続は非単調劣化の前例が濃い: warm4k→12k→40k 単調悪化・v10 の wait 点灯は iter60 のみ。終端1点の測定は消灯位相を引く危険)。→ weekC で評価。weekB でも評価(in-sample 上限、診断用)。
- **腕3 週スクラッチ**: fast100 そのもの → weekC。

**統計の扱い(事前登録)**:
- 帯は記述用。同一 run の5帯は独立でないため「4/5帯」を有意性の根拠にしない。
- **placebo 較正**: fast100 の iter80 vs iter100 を weekC で掃引し、隣接 checkpoint 間で帯勝敗がどれだけ揺れるかをノイズ床とする(追加学習ゼロ、掃引2本)。腕間の差はこの床を超えて初めて意味があるとする。
- 安い腕(適応)は 2-3 seed。M_A は n=1 を受け入れ、結論は「この M_A に条件付き」と明記。
- 50k 直接学習の seed 間分散は未測定(fast100 の3run 一致はビット一致=同一乱数であり分散の証拠ではない)。適応腕の複数 seed が最初の分散データを兼ねる。

**判定**:
- 腕2(軌跡最良) > 腕1 + placebo床: 適応に利得あり。
- 腕2 ≈ 腕1.5: **利得の実体は再較正**。運用は「学習不要・毎週再較正のみ」に簡素化(これも強い結論)。
- 腕3 ≥ 腕2: 毎週スクラッチが正解。warm 引き継ぎの運用像は棄却。
- 全腕 < 腕0: PCN 週次運用そのものに価値なし(現状の率直な答えとして報告)。

### 3.4 第2段: 持ち越し設計の因子実験(条件付き・smoke規模)

第1段で腕2 に正味の利得(腕1.5 超え)があった場合のみ。replay 持ち越し × frozen PF × 正規化の 2^3 を sub4096 級で、**セルあたり 2-3 seed**(小規模は分散が大きい: ±25pt、崩壊は確率的)。結論は「08-05 の占拠機序が週跨ぎで再現するか」の機構スクリーニングに限定し、5万への外挿はしない。

### 3.5 第3段: 運用リハーサル(4連続週)

week0→A→B→C の連鎖で完全プロトコル。占有状態の週跨ぎ連続(Wall A)はここで初めて入れる。**選点は膝1点のみで1本走らせる**(選点3点だとチェーンが分岐して学習コスト3倍)。選点感度は最終週だけ3点に分岐して測る。

**成否の定義**: 「できる」= 約束ずれが週を追って拡大しない AND 適応ありが凍結+placebo床を毎週上回る。「できない」= どちらかが破れる。**どこで破れたか(正規化/アーカイブ/分断/方策の質)を §3.2 の分解で機序まで特定して初めて実験成立**とする。
