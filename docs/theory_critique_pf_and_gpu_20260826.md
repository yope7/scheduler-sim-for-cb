対象=現行v9構成: オンラインPCN(REFIT_EVERY=0)、5万ジョブweekB、NITER=100、16本/iter、
replay上限300本(非支配+crowding淘汰)、Phase1=rawカーネル+CPUリプレイ、Phase3=CPU Actor、eval=lockstep。

## Q1. PFを発見して再現できるか

### 結論(先に)

> **マクロ骨格の発見と再現は高い確度で可能(探索でなく設計で保証+実績あり)。
> 中域を掘る「改善のラチェット」は、今回の修正群でようやく論文の形で回る=100iterで初めて本試験になる。
> 微細なPF内挿は島構造(問題の幾何)で制限され、これはアルゴリズムの欠陥ではない。
> 最大の残存リスクは100オンラインiterでの条件付け崩壊。**

### 発見(discovery)を4段に分解して評価

**① 骨格の発見 — 保証されている(探索に依存しない)**
Phase1のBernoulli掃引 p∈{0, 0.1, 0.25, 0.5, 0.75, 0.9, 1}×192本が、PFのマクロ骨格(クラウド率の連続体)を最初から張る。この問題は2目的のマクロがpでほぼ決まる(過去実測: ランダムp掃引がHV89-97%)ため、**骨格は学習前に手に入る**。cheap端(p<0.2)を捨てていたバグは修正済み=cost最小端も入る。

**② 骨格の内挿 — 条件付け汎化。動くが量子化する**
NNは指令(cost,wait)で条件付けられ、アーカイブ点の間を内挿する。実績: 未知seedの真PFに乗る(過学習なし)。限界: 5万での出力は7〜18種に量子化(v3/v6実測)。原因は③の幾何+条件付けの分解能。

**③ 幾何的上限 — 島構造(アルゴリズムの外側の制約)**
2^18全列挙による証明済み事実: 実行可能集合は巨大ジョブの雲送り本数で島に分断され、**ギャップ内の指令は誰にも達成できない**。「PFを完全な連続体として発見する」ことは問題として不可能。正しい目標は「各島の非支配点を発見し、島の代表点を再現する」であり、これは達成可能。

**④ 改善のラチェット — 今回の修正でようやく論文の形になった**
「非支配点+σナッジの指令 → rollout → hindsight学習 → 賢くなった方策でさらに先へ」の反復が
PCNの改善エンジン。これまでの5万構成では**三重に壊れていた**:
- refit方式: 方策改善が25iterに1回(廃止済み)
- Phase2=0エポック: 最初の25iterが乱数方策(修正済み)
- **淘汰がFIFO**: 発動した瞬間にPF端点から消える(今回発見・Eq.6-7忠実化済み。単体実証: far-dominated→near-dominated→密集ND→疎らND の段階的淘汰、端点保護を確認)

つまり**「PCNとして正しく回る100iter」は今回が初**。過去の5万結果(v3/v6)からの外挿でラチェットの効きを予言することはできない——これが正直な現在地。

### 再現(reproduction)の成立条件

| 条件 | 状態 |
|---|---|
| 教師ラベル規約=eval規約 | ✅ `PCN_LABEL_G=1`(ビタ再現実証: 正規約なら一致63%・L2中央値0.0000=網は無罪) |
| evalの決定性 | ✅ 今回確立(Actor側`model.eval()`固定。従来はdropoutノイズでbest選抜が揺れていた) |
| 端点・分布外指令 | △ 較正層(逆写像較正)がeval時対処として実績あり(HV89%・両端gap0%) |
| **条件付け崩壊** | ⚠️ **最大の残存リスク**(下記) |

### ⚠️ 崩壊リスクの正直な評価

100オンラインiterは、まさに「iter10完璧→iter50最悪」が観測された領域。hindsight relabelingは
指令を状態から冗長にする構造的な圧力を持つ(崩壊の根、07-06特定)。現在生きている対策:

| 対策 | v9での状態 |
|---|---|
| s_embドロップアウト(指令を使わざるを得なくする) | ✅ **今回復活**(0.08)。昨日私がeval決定性のために0にしたのは誤り寄りで、「学習はdropout維持・Actorはeval()固定」に修正 |
| 感受性KL(同一obsで指令を変えたら方策も変わることを強制) | ✅ 0.04(プロファイル) |
| Fourier指令エンコード | ✅ ON(≥64で有益の実績) |
| **cmd_track損失(崩壊除去のstrict win実績)** | ❌ **どのプロファイルにも入っていない** |

**推奨**: `PCN_CMD_TRACK_WEIGHT=0.3`を追加する。trace256/512でstrict win、片側lossで副作用小。
8時間の投資が崩壊で無駄になる期待損失の方が、レシピ変更のリスクより大きい。
(対案=「まず無しで回し、cmd_track距離のログを監視して兆候が出たら足す」も科学的には正当。指標はログに出ている)

### その他の理論的注記(小さいが記録)

- **実効サンプルは軌道300本**(遷移15Mではない)。方策の多様性はバッファの軌道多様性が上限——だからこそ淘汰の質(Eq.6-7)が効く
- **f32累積の量子化**: cost累積1.6e10でfloat32の刻み≈2048。末尾ステップのR_tラベルは相対1e-7の粗さ。総和には無害だが、近接指令の区別の理論限界として残る(f64化は将来課題)
- 教師重み付け(DEDUP等)は論文の一様サンプリングからの逸脱として残存(実績ある調整として容認)
- horizonの-2非対称は5万では0.004%で無視可能

## Q2. GPUはメモリ・計算効率から最適化されているか

### 結論(先に)

> **無駄の除去は完了したが、「GPUを使い切る」設計ではない。GPU1のduty比は約10%。
> これはPCNの「少量・頻回」という性質とGPUの「大量・一括」という体質の本質的な相性問題であり、
> 現構成は『ループはCPUで小さく速く回し、GPUは生成と評価に使う』という意図的な妥協。**

### duty比の実態(NITER=100、約8-9時間の見込み内訳)

| 資源 | 働く場面 | duty比(概算) |
|---|---|---|
| GPU1(工場) | Phase1生成 ~6分 + eval 5回×~10分 | **~10%** |
| GPU0(Learner) | update 100回/iter(cap300のGPU cacheなら~10-30秒)+Phase2 ~7分 | ~10-20%(async overlapでrolloutの裏に隠れる) |
| CPU 64コア | **Phase3 rollout(16 Actor×3.3分/iter)= ループの主役** + obsリプレイ | 高 |

### なぜこうなるか(実測に基づく構造)

- 16本/iterの少量生産では、lockstep(T=50000逐次で1チャンク定額~10分)がCPU Actor(12.4秒/本×16並列=3.3分)に**3倍負ける**(実測)
- lockstepのB拡大はタダ(B=256で1本3秒)だが、**学習側が受け止められない**(replay上限300・教師cache 916B/遷移・そして論文の10本/iterという形)——「全GPU化はデータ量を16倍にする時だけ得」という構造が実測で確定している
- つまり**壁時計最適とGPU利用率最大化が両立しない**のが現在の実力

### 除去済みの無駄(今回までの監査の成果)

warmupのXLA空回し12分+~9GiB / E_MAX 12倍過剰(65536→8192、実測peak 3654) / cheap端29%捨て /
教師cacheの2倍ピーク / GCスラッシング(gen2走査113.7ms→0.1ms) / snapshot 31分ブロック(exit134) /
評価127分の格子(学習中OFF化)。**「無駄の除去」の次元では最適化済み**。

### メモリの現状(cap300前提)

| 領域 | 使用量 | 判定 |
|---|---|---|
| GPU0: 教師cache | 12.8GiB定常(2倍ピーク解消済) | ✅ 44GiBに余裕 |
| GPU1: rawカーネル(E_MAX=8192) | 54MiB/本 | ✅ |
| CPU RAM: replay 300本 | ~28GB(配列+オブジェクト) | ✅ 503GBに余裕 |
| Ray object store | Phase1配列 ~8.8GBピン留め vs 16GB | △ 端に近いが淘汰で解放される |

### GPUを本当に使い切りたい場合の唯一の道

lockstepの1ステップ13.7msの内訳は**NN forward 180μs(1.3%)+環境step/obsカーネル(98.7%)**。
つまりボトルネックはNNでなく環境カーネルで、
- obsカーネルの増分化の続き(4.16→1.76倍まで来ている)
- 5発行/周のCUDA Graph化
- step/obsカーネルの融合
で1ステップ数msまで下げられれば、lockstepがCPU Actorに少量でも勝ち、全GPU化が成立する。
これは「効率化」でなく**カーネル研究**の投資判断。現時点では回さない(壁時計が正義)が、
論文の「1000本/分級の生成能力」はデータ拡大方向(INITEP増・アンサンブル・多seed)にいつでも使える。
