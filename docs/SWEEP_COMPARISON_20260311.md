## 分析

### 1. イベント観測による高速化

- **観測空間の縮小**: ビットマップ版は `H_onpre×obs_window + H_cloud×obs_window + 40`（例: 256×10 + 1024×10 + 40 = 12,840次元）に対し、イベント版は `30×4 + 40 = 160次元`。
- **計算負荷の軽減**: 観測の構築・転送・ニューラルネットの入力を大幅に削減。
- **全フェーズで短縮**: P1（Actorの観測取得・推論）、P2（バッチ学習）、P3（改良エピソード生成）のいずれも短縮。

### 2. フェーズ別の短縮率

| フェーズ | 役割 | 短縮の主因 |
|----------|------|------------|
| P1 | 初期エピソード収集 | 観測構築の軽量化、Actorの推論負荷低下 |
| P2 | 教師あり学習 | バッチ内の観測サイズ縮小による学習の高速化 |
| P3 | 改良された経験の実現 | エピソード生成時の観測・推論の軽量化 |

### 3. スケール特性

- **ノード数増加時**: (512,2048) は (256,1024) よりビットマップ版で顕著に遅かったが、イベント版では差が小さくなっている（観測がノード数に依存しないため）。
- **ジョブ数増加時**: 64 jobs でも最新版は 100秒以内に収まり、ビットマップ版の 311秒から大きく短縮。

### 4. 結論

イベントベース観測への移行により、**実行時間が約 55〜69% 短縮**され、特に大規模構成（64 jobs、512×2048）で効果が大きい。観測の簡素化が学習パイプライン全体の負荷を下げている。
